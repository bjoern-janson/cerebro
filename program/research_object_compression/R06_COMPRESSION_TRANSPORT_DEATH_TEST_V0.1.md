## Attack A — `PRIMARY_SOURCE_RECURRENCE_AS_WARRANT_MULTIPLICITY`

The compressed item:

```text
R06:HYPOTHESIS:CORE_INTELLIGENCE
```

has seven distinct source occurrences across README, core theory, elasticity, mathematical formalization, benchmark vision and formalization files.

The compression correctly collapses their closely related semantics and preserves every source branch.

However, it currently records only:

```text
source_parse_units
source_role_branches
```

It does not explicitly state whether those seven source occurrences are independent warrants, dependent restatements, shared-lineage restatements, or merely repeated source expression.

A future network could therefore mistake:

\[
7\ \text{source occurrences}
\]

for:

\[
7\ \text{independent support branches}.
\]

This is not licensed.

\[
\boxed{
\text{source-occurrence multiplicity}
\neq
\text{warrant independence}
\neq
\text{warrant multiplicity}.
}
\]

```text
PRIMARY_SOURCE_RECURRENCE_AS_WARRANT_MULTIPLICITY = HIT
```

Failure locus: compression derivation / warrant-accounting semantics.

This differs from Amendment 003's `SECONDARY_REUSE_WITHOUT_ROLE`:

- Amendment 003 governs multiple representations of the **same parse unit**;
- R06 exposes multiple **distinct source parse units** with related/duplicate semantic content.

The new problem therefore cannot be repaired merely by the existing secondary-alias rule.
